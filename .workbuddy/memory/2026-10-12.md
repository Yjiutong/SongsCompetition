## Bug 修复：二选一界面白屏（约 22:10）
- 现象：进入 playing 后「你的对阵」面板空白（轮次条 `第 1/1 轮` 正常），「本轮所有人的选择」也不出内容。
- 根因：**前后端数据形状不一致**。`room.js` 的 `publicView()` 把本轮对阵输出为 `pairs: [{a, b, pick}]`（选择直接挂在每个对阵的 `pick` 上，`picks` 对象只存在于 DO 内部存储）；而 `app.js` 的 `renderPlaying()` 读的是 `mine.picks[idx]` → `undefined[0]` 抛 TypeError → `render()` 在渲染「你的对阵」时中断，`innerHTML` 刚被清空、卡片还没 append，于是面板空白且公示板也没轮到渲染。
- 修复：`public/app.js` 改为读 `pr.pick`；并顺手加固：
  - `render()` 拆成 `render()`（try/catch）+ `renderInner()`，任何渲染异常都会 console.error + toast 提示，不再静默白屏；
  - `renderPlaying()` 区分三种情况给出明确文案：身份同步中 / 旁观者（提示下一局自动参赛）/ 等待开局。
- 验证（本次新增两个临时脚本，位于 `.workbuddy/tmp/`，已加入 .gitignore，不参与部署）：
  - `.workbuddy/tmp/room.test.mjs`：mock DurableObjectState 驱动 Room 状态机走完整局（4 首→开始→各选2组→roundComplete→next_round→再选→finished→reset），20 项断言全过，确认后端契约。

## Bug 修复：管理后台登录报 HTTP 500（约 22:45）
- 现象：`/admin` 页面能打开（静态资源正常），输入 ADMIN_TOKEN 点「进入后台」显示红色 `HTTP 500`。
- 根因（两处，都是致命错误）：
  1. **`DurableObjectNamespace` 根本没有 `list()` 方法**。官方文档确认运行时命名空间只有 `idFromName / newUniqueId / idFromString / get / getByName / jurisdiction`，枚举对象只能走 REST API。原 `listRooms()` 调 `env.ROOM.list(...)` → `TypeError: not a function` → Worker 未捕获 → 500。（`list()` 只存在于 REST API `GET /accounts/../durable_objects/namespaces/:id/objects`。）
  2. **`Room` 是普通类（未 `extends DurableObject`），不支持 RPC**，`stub.adminView(name)` 调不通（原代码被 try/catch 静默吞掉，即便 list 可用也只会得到空列表）。
- 修复方案（改成不依赖 RPC、也不依赖 list）：
  - **房间索引**：用同一个 `Room` 类的保留实例 `__rooms_index__`（`INDEX_NAME`）存 `{房间名: lastSeen}`。有人进房间时 Worker 登记（`/ws` 用 `ctx.waitUntil`，`/state?reg=1` 用 await）；`registerRoom` 5 分钟内重复登记走缓存避免写放大，并顺手清理 7 天前的名字。客户端房间名以 `__` 开头直接 400（保留前缀）。
  - **DO 内部 HTTP 接口**取代 RPC：`Room.fetch` 新增 `/__admin/view`、`/__admin/act`、`/__index/register`、`/__index/list`；Worker 用 `stub.fetch(INTERNAL+path, init)` 调用（`callDO`）。外部请求到不了这些路径（Worker 只转发 /ws 与 /state）。
  - **全局兜底 try/catch**：`export default { fetch }` 包住 `handle()`，任何异常都返回 `{error,message,hint,stack}` 的 500 JSON，后台页面改为展示 `message`，不再只有「HTTP 500」。
  - 新增 **`/admin/api/ping`** 自检（tokenConfigured / indexOk / indexErr / indexedRooms）；后台页面显示「索引房间 N 个」，并新增「按房间名直达」输入框（列表没有的历史房间也能查/管）。
  - `room.js` 顺手加固：`computePairs/hasPickedAll/adminView/adminAction/publicView` 对缺失 `survivors` 的旧房间状态用 `|| []`，避免旧数据把后台打挂。
  - `public/app.js`：首次轮询 `/state` 带 `&reg=1`（WS 被拦时也能登记房间）。
- 测试：重写 `.workbuddy/tmp/admin.test.mjs`（40 项断言全过）——用「内存版 Durable Object 命名空间」把 Worker 的 `stub.fetch` 转发进**真实 Room 实例**，端到端验证：403 鉴权、索引空→空数组、`/state?reg=1` 登记、列表计数与真实房间一致、详情、POST 操作落到 Room 状态、未知操作 400、广播 notice、按名直达、ping、`__` 前缀 400、/admin 页面 no-cache、/ws 不被鉴权拦截且登记生效、DO 抛异常时 500 带可读 message。四套测试（room/render/worker/admin）全过。
- 注意：改后**只有「有人进入过」的房间**才出现在后台列表里（旧房间需重新进入一次）；这是运行时无 list() 的必然取舍，README 已写明。
